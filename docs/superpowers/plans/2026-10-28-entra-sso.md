# Entra ID SSO Plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Đăng nhập/đăng ký Plane bằng Microsoft Entra ID (một tenant) dưới dạng plugin `plane.ee.entra_auth`, kèm trang đăng nhập chỉ-provider và `/login/internal`.

**Architecture:** Lớp cơ sở `OIDCProvider` (discovery, PKCE, nonce, xác thực id_token) + `EntraProvider` (issuer theo Tenant ID, ảnh qua Graph). Tổ chức **theo đúng khung EE của work-item-types** (xem mục "Quy ước EE"): code mới nằm trong `apps/api/plane/ee/entra_auth/` và `apps/{web,admin,space}/ee/entra-auth/`; core chỉ có điểm nối nhỏ nằm trong `deployments/ee/core-allowlist.txt`, tận dụng các seam `extended` đã có (`instance_config_variables/extended.py`, `routes/extended.ts`, `hooks/oauth/extended.tsx`).

**Tech Stack:** Django/DRF, PyJWT 2.15.1 + cryptography (đã có), requests, django cache (Redis); React Router (web, admin, space), MobX, `@plane/i18n`.

**Spec:** `docs/superpowers/specs/2026-10-28-oidc-entra-design.md`

## Global Constraints

- Một tenant; `tid` trong token phải bằng `ENTRA_TENANT_ID`. Tenant ID phải đúng dạng GUID.
- Redirect URI gửi đi và đăng ký trong Entra: `https://<host>/auth/entra/callback` (không có `/` cuối); URL pattern nhận cả `callback` và `callback/`.
- Định danh = `oid` (`provider_id`). Tên hiển thị = claim `name` → `first_name`, `last_name` để trống.
- Scope: `openid email profile User.Read`. Chỉ thuật toán `RS256`. PKCE `S256` + `nonce`; `state` dùng lại `validate_oauth_state`.
- Không thêm dependency mới. Không sửa core ngoài các điểm nối ghi trong từng task; mỗi file core chạm tới phải vào `deployments/ee/core-allowlist.txt` **trong chính task đó** và `bash scripts/check-core-allowlist.sh preview` phải exit 0 (xem "Quy ước EE").
- Mã lỗi mới: `ENTRA_NOT_CONFIGURED` 5126, `ENTRA_PROVIDER_ERROR` 5127, `ENTRA_EMAIL_UNUSABLE` 5128.
- Khóa cấu hình (category `ENTRA`): `IS_ENTRA_ENABLED`, `ENTRA_TENANT_ID`, `ENTRA_CLIENT_ID`, `ENTRA_CLIENT_SECRET` (mã hóa), `ENTRA_PROVIDER_NAME`, `ENTRA_ALLOWED_EMAIL_DOMAINS` (chuỗi phân tách dấu phẩy), `ENABLE_ENTRA_SYNC` (mặc định `0`), `SSO_ONLY_LOGIN_PAGE` (mặc định `0`).
- Frontend: `pnpm check:types`, `pnpm check:lint`, `pnpm fix:format` phải sạch. Web/admin/space không có framework unit test, kiểm bằng type-check + duyệt trình duyệt.
- Chỉ dùng `docker-compose.yml`, `docker-compose-local.yml`, `docker-compose-test.yml` (không dùng file overlay ee).
- Chạy test backend: `docker compose -f docker-compose-test.yml run --rm --build api-tests pytest <đường dẫn> -v`.

## Review Focus

Các tình huống spec ngầm đòi nhưng dễ bị bỏ sót, theo thứ tự dễ gặp:
1. Token ký hợp lệ nhưng thuộc **tenant khác** (`tid`/`iss` sai) → từ chối (Task 3).
2. **Nhầm thuật toán**: token `alg=none` hoặc `HS256` ký bằng chính client secret → từ chối (Task 3).
3. **Phát lại callback**: dùng lại cùng `state`/`nonce`/`code_verifier` lần hai → từ chối (Task 4, 6).
4. Ảnh Graph lỗi (`404`, `403`, redirect sang host lạ): đăng nhập vẫn thành công, token không bị gửi sang host khác, ảnh cũ không bị xóa, không lưu URL Graph vào `user.avatar` (Task 5).
5. **Vòng lặp tự redirect** sau lỗi đăng nhập hoặc sau đăng xuất, và instance bị khóa khi không provider nào bật (Task 9).

Còn lại có test ở task tương ứng: email hoa/thường, `ENABLE_SIGNUP=0`, thiếu email, domain không được phép, thiếu `name`.
